Application 1: Access the System
1.1.
Access the Support Ticketing System
  • Open any web browser available in your computer and enter the official STS web address provided by the ICT Section.
 You will be redirected to the Log-in Page of the Support Ticketing System, displaying the Welcome Back form with the Username and Password fields, the Show Password (eye) icon, Remember me, and the Sign In button, over the Quality Policy background.
1.2.
Verify the Log-in Page branding
  • Check the form and footer of the Log-in Page.
 The page shows the National Museum of the Philippines Support Ticketing System branding (NMP logo and Welcome Back heading) and the Privacy Policy and Terms of Use links in the footer.
Application 2: Login
2.1.
Login to STS
Format:
Username:
“Museum organization username”
Password:
“PAMANA password”
  • Enter your correct credentials (username and password);
  • Click the Sign In button.
 The Sign In button shows Signing in… while processing. You will be logged in and redirected to the landing page of your assigned role (Staff/Client, Admin, Records, or Super Admin).
2.2.
Login with an incorrect password
  • Enter your correct username and an incorrect password;
  • Click the Sign In button.
 The system does not sign you in and displays the message Incorrect email or password.
2.3.
Login with an incorrect username
  • Enter an unregistered username and any password;
  • Click the Sign In button.
 The system does not sign you in and displays the message Incorrect email or password.
2.4.
Login with a blank username
  • Enter your password and leave the username field blank;
  • Click the Sign In button.
 The system does not sign you in and prompts you to fill in the Username field.
2.5.
Login with a blank password
  • Enter your correct username and leave the password field blank;
  • Click the Sign In button.
 The system does not sign you in and prompts you to fill in the Password field.
2.6.
Login with both fields blank
  • Leave both username and password fields blank;
  • Click the Sign In button.
 The system does not sign you in and prompts you to fill in the required fields.
2.7.
Show and hide your password
  • Type a password in the Password field;
  • Click the eye icon.
 The password characters are shown. Clicking the eye icon again hides them.
2.8.
Use the Remember me option
  • Enter your credentials and tick Remember me;
  • Sign in, then log out;
  • Open the Log-in Page again in the same browser.
 Your username is saved on this browser and is already filled in on the Log-in Page.
2.9.
Logout
  • Click Logout at the bottom of the left sidebar.
 Your session is ended and you are returned to the Log-in Page.
Application 3: Multi-Factor Authentication (MFA)
3.1.
Open the Set up MFA dialog
  • Log in using valid account credentials;
  • Click Set up MFA at the bottom of the left sidebar.
 The MFA dialog is displayed. It explains that an authenticator app (Google Authenticator or Microsoft Authenticator) will ask for a code in addition to your password when signing in.
3.2.
Complete the MFA setup
  • Enter your current password and click Set up MFA;
  • Scan the QR code or enter the Setup key in your authenticator app;
  • Save the Recovery codes shown on the dialog (they are shown only once);
  • Enter the Code from the app and click Confirm and enable.
 MFA is turned on for your account. The message Multi-factor authentication enabled is displayed.
3.3.
Login with MFA turned on
  • Enter your correct username and password;
  • Click the Sign In button;
  • Enter the 6-digit code from your authenticator app in the Authentication code field.
 After the correct credentials, the page asks for the Authentication code (placeholder: 6-digit code or recovery code). After the correct code is entered, you are logged in.
3.4.
Login using a recovery code
  • Enter your correct username and password;
  • Enter one of your saved recovery codes in the Authentication code field.
 The page accepts a recovery code in place of the 6-digit code and logs you in.
3.5.
Login with an incorrect code
  • Enter your correct username and password;
  • Enter an incorrect Authentication code.
 The system does not complete the sign-in, displays The authentication code is incorrect., and does not open the dashboard.
Application 4: Settings and Account Profile
4.1.
Open the Settings page
  • Click Settings at the bottom of the left sidebar.
 The Settings page is displayed with the Account panel showing Email, Role, Display name, Division / office, Designation, and the Save profile button.
4.2.
Verify the read-only fields
  • Try to edit the Email and Role fields.
 Email and Role are displayed but cannot be edited. Role shows Admin.
4.3.
Update your profile
  • Update the Display name, Division / office, and Designation;
  • Click the Save profile button.
 The button shows Saving… and the profile is saved. The message Profile updated is displayed. The updated display name appears in the portal header and in the activity logs.
4.4.
Save the profile with required fields blank
  • Clear the Display name or the Division / office field;
  • Click the Save profile button.
 The profile is not saved. The message Name and division are required is displayed.
4.5.
Verify the Password section
  • Check the Password section of the Settings page.
 The page states that the sign-in password is the PAMANA password and cannot be changed in STS. To change it, change the password in PAMANA and then sign in with the new password.
Application 5: Notifications
5.1.
Open the notification bell
  • Log in as Admin;
  • Click the notification bell in the header.
 The Notifications dropdown opens, showing the number of items (or You're all caught up). It lists pending client approvals, tickets ready for personnel assignment, assigned work, new messages, and pokes.
5.2.
Open an update from the bell
  • Click a ticket update in the dropdown.
 The dropdown closes and the related Approvals or Request Management page opens. A message or poke update opens the Messages window instead.
5.3.
Verify the empty notifications
  • Open the bell when you have no updates.
 The dropdown shows No pending client requests.
5.4.
View all notifications
  • Click View all at the bottom of the dropdown when items are listed.
 The Approvals page is displayed.
Application 6: Messages
6.1.
Open the Messages window
  • Click MAIN, then Messages, in the left sidebar (or click the chat button at the lower right of the screen).
 The floating Messages window opens over the page with the New button, the Search chats box, and your chats grouped under Requests and Direct messages. The unread count appears on the chat button and the sidebar. (Messages is not a separate full page.)
6.2.
Verify the empty chat list
  • Open the Messages window when you have no chats.
 The window shows No chats yet. Start one with New.
6.3.
Search your chats
  • Type a name or request in the Search chats box.
 The list is filtered to match. When nothing matches, the window shows No chats match your search.
6.4.
Open the New message window
  • Click the New button.
 The New message window is displayed with the note Message or poke anyone: admin, records, or client., the search box (Search by name, email, or division…), and the Admin and Clients groups, each user with a Poke button.
6.5.
Search for a user
  • In the New message window, type a name, email, or division in the search box.
 The list is filtered to match what you typed. When there is no match, it shows No people found.
6.6.
Start a direct conversation
  • Click the name row of a user.
 A private direct chat with that user is created and opened. When there are no messages yet, it shows No messages yet and Send the first message below.
6.7.
Send a message
  • Type a message in the Message <name>… field;
  • Click the Send button or press Enter.
 The message appears in the thread instantly and is delivered in real time to the other person.
6.8.
Mention a user
  • Click the @ button or type @ in the message field;
  • Select a person from the list;
  • Send the message.
 The selected person is tagged in the message.
6.9.
Poke a user
  • Click the Poke button beside a user in the New message window, or the Poke button in the chat header.
 The message Poked <name>! is displayed. The user receives an instant alert in the notification bell without a full conversation.
6.10.
Open the request chat
  • Open a ticket from Approvals, Request Management, or Assigned to me;
  • Click the Request messages button.
 The chat for that request opens with the status, the form title, and the message field Message about this request….
6.11.
Receive a new message
  • Have another user send you a message while you are on another page.
 The unread badge on the chat button updates. When you are scrolled up in a thread, the New messages button appears and scrolls you to the latest message when clicked.
6.12.
Close the Messages window
  • Click the X button, or click outside the window.
 The window closes and the chat button is shown again.
Application 7: Admin: Dashboard and Navigation
7.1.
Verify the Admin dashboard after login
  • Log in as Admin.
 The Admin dashboard is displayed with the welcome banner (Good day, <first name>), the Review approvals and Open Form Builder buttons, the Requests to approve, Pending review, and Draft forms stats, and the Today's activity panel.
7.2.
Verify the sidebar menu
  • Expand MAIN, FORMS, and REQUESTS in the left sidebar.
 MAIN shows Dashboard, Reports, and Messages. FORMS shows Form Builder and Published Forms. REQUESTS shows Approvals, Request Management, Assigned to me, My Requests, and Submit Request. Settings, Set up MFA, and Logout are at the bottom. Menu items show a count when something needs your action.
7.3.
Open Approvals from the dashboard
  • Click Review approvals in the welcome banner, or click the Requests to approve stat.
 The Approvals page is opened.
7.4.
Open Form Builder from the dashboard
  • Click Open Form Builder in the welcome banner, or click the Pending review or Draft forms stat.
 The Form Builder page is opened.
7.5.
Verify the assigned-requests alert
  • Have a ticket assigned to your account;
  • Open the dashboard.
 The alert You have assigned requests is shown with the Open My Assignments button.
7.6.
Verify the form-revision alert
  • Have a form returned by Records with status Disapproved;
  • Open the dashboard.
 The alert that forms need revision is shown with the Records remarks and the Open Form Builder button.
7.7.
Verify the pending-approvals alert
  • Have client requests waiting for your Action Officer approval;
  • Open the dashboard.
 The alert that client requests are awaiting approval is shown with the Open Approvals button.
7.8.
Verify Today's activity
  • Check the Today's activity panel.
 Recent Admin actions for the current day are listed. When there is none, the panel shows that there is no activity yet today.
7.9.
Verify the profile menu
  • Click the profile area in the top-right header.
 The user name and role details are displayed.
Application 8: Admin: Form Builder
8.1.
Open the Form Builder
  • Click FORMS, then Form Builder, in the left sidebar.
 The New request form page is displayed with the six steps: General, Fields, Print Template, Client Request Approval, Workflow, and Supporting Doc, and the progress shows Step 1 of 6.
8.2.
Verify the General information step
  • Check the General information section.
 The section shows Form title, Reference number (auto-generated), Date effectivity, Version number, and Division/Section (taken from your PAMANA login / section).
8.3.
Complete the General information
  • Enter a Form title;
  • Select a Date effectivity;
  • Click the Continue button.
 The system opens the Fields step (Step 2 of 6).
8.4.
Continue without a title or effectivity
  • Leave Form title or Date effectivity blank;
  • Click the Continue button.
 The system does not proceed and displays Enter a form title before continuing. or Choose a date effectivity before continuing.
8.5.
Verify the Form elements
  • Open the Fields step and check the Form elements panel.
 The panel lists Textbox, Textarea, Dropdown, Checkbox, Radio, Date Picker, Time Picker, Date & Time, File Upload, Email, Number, and Signature.
8.6.
Add form fields
  • Click an element, such as Textbox, in the Form elements panel;
  • Add other element types.
 Each element is added to the Live preview, which shows what employees will see when filling in the form.
8.7.
Edit the field settings
  • Select a field in the Live preview;
  • Change its Label and Placeholder;
  • Tick Required field.
 The Field settings panel shows the Label, Placeholder, Required field option, and the field Variable. The Live preview updates with your changes.
8.8.
Reorder the fields
  • Drag a field row in the Live preview to a new position.
 The fields are shown in the new order.
8.9.
Continue without adding a field
  • Open the Fields step without adding any field;
  • Click the Continue button.
 The system does not proceed and displays Add at least one form field before continuing.
8.10.
Go back to the previous step
  • Click the Back button.
 The previous step is displayed and the information you entered is kept.
8.11.
Upload the printable PDF template
  • Open the Print Template step;
  • Upload a printable PDF form (maximum 25 MB).
 The PDF is displayed in the template editor. A multi-page PDF is shown with its pages stacked for field mapping.
8.12.
Upload a template larger than 25 MB
  • Open the Print Template step;
  • Upload a PDF larger than 25 MB.
 The system does not accept the file and displays File is too large (max 25 MB). Try compressing the PDF.
8.13.
Map the fields on the template
  • Place each form field on its position in the printable template;
  • Review the alignment and spacing;
  • Click Continue.
 Each field is shown at its mapped position on the template. Continuing without a template or placements shows Upload a form template before continuing. or Place at least one field on the template before continuing.
8.14.
Configure the Client Request Approval
  • Open the Client Request Approval step;
  • Set Recommending Officer to Yes;
  • Set Immediate Supervisor to Yes.
 The Recommending Officer and Immediate Supervisor stages are enabled and shown in the Live Workflow Preview (Client → Recommending Officer → Immediate Supervisor → Process Owner).
8.15.
Verify the Immediate Supervisor option
  • Set Recommending Officer to No;
  • Check the Immediate Supervisor option.
 The Immediate Supervisor option is hidden. It can only be enabled while Recommending Officer is Yes.
8.16.
Configure the Workflow
  • Open the Workflow step;
  • Select at least one Action Officer from your PAMANA section;
  • Arrange the Action Officers in the processing order (AO1 → AOn).
 The Action Officers are listed in the configured order. Earlier officers are Approval; the last Action Officer is Request Management and is responsible for personnel assignment after approvals.
8.17.
Continue Workflow without an Action Officer
  • Open the Workflow step without selecting an Action Officer;
  • Click the Continue button.
 The system does not proceed and displays Select at least one Action Officer before continuing.
8.18.
Add the Supporting Doc
  • Open the Supporting Doc step;
  • Upload an optional supporting PDF (maximum 25 MB).
 The supporting PDF is attached to the form. The step is optional, so the form can also continue without it. A non-PDF is rejected with Only PDF files are allowed.
8.19.
Save the form as a draft
  • On the last step, click Save as draft instead.
 The form is saved with the status Draft. The message "<title>" saved as draft is displayed. Drafts do not appear in Records. The Draft forms count on the dashboard increases.
8.20.
Submit the form to Records
  • Complete all six steps;
  • Click Submit to Records.
 The form status changes to Pending Review. The message "<title>" submitted to Records is displayed. The form appears in the Pending Forms of the Record Admin.

Application 10: Admin: Approvals
10.1.
Open the Approvals queue
  • Click REQUESTS, then Approvals, in the left sidebar.
 The Approvals page is displayed as the Action Officer queue, with the pending count in the header and the table showing Ticket, Client, Division, Status, and Action.
10.2.
Refresh the queue
  • Click the Refresh button in the upper right corner.
 The button shows Refreshing… while loading. The table is updated with the latest submissions.
10.3.
Open Request Management from the queue
  • Click the View all requests → link at the bottom.
 The Request Management page is opened.
10.4.
View the submitted file
  • Click View file beside a ticket.
 A read-only preview of the generated request form is displayed.
10.5.
Approve a request (intermediate Action Officer)
  • As an intermediate Action Officer, click Approve beside a request.
 The message Request approved is displayed. The ticket remains in the approval workflow for the next Action Officer.
10.6.
Approve a request (final Action Officer)
  • As the last Action Officer (Request Management role in the form workflow), click Approve.
 The message Approved — ready for task assignment is displayed and you are taken to Request Management to assign personnel.
10.7.
Reject a request without a reason
  • Click Reject beside a request;
  • Leave the Reason for rejection blank.
 Confirm reject stays disabled. The request is not rejected, because a rejection reason is required.
10.8.
Reject a request with a reason
  • Click Reject beside a request;
  • Enter the reason;
  • Click Confirm reject.
 The message Request rejected is displayed. The ticket status becomes Rejected and the reason is provided to the requestor.
10.9.
Verify the empty queue
  • Open the Approvals page when no approvals are pending.
 The page shows No pending approvals. New client requests will appear here for your review.
Application 11: Admin: Request Management and Assignment
11.1.
Open Request Management
  • Click REQUESTS, then Request Management, in the left sidebar.
 The page shows the master tracking queue with the request count in the header and the table showing Ticket, Client, Division, Status, and Action.
11.2.
View the request file
  • Click View file on a ticket.
 A read-only preview of the generated request form and any attached files is displayed.
11.3.
Use the preview controls
  • Click the − and + buttons;
  • Click Reset;
  • Scroll through the preview.
 The document zoom is changed and the scale percentage is updated. Reset returns the view to its default, and all pages of the form can be checked.
11.4.
Close the preview
  • Click the X button of the preview.
 The preview is closed and you return to the Request Management queue.
11.5.
Open the ticket details
  • Click Manage → on a ticket.
 The full ticket details page is displayed, where you can assign personnel (when ready), update the status (where allowed), and open Request messages.
11.6.
Assign personnel to a ticket
  • Open a ticket that is ready for task assignment;
  • Select one or more personnel from your PAMANA section list;
  • Click Assign.
 Only active personnel from your section are listed. The message Personnel assigned is displayed. The ticket status becomes In Progress, and the ticket appears in Assigned to me of the assigned personnel.
11.7.
Update the ticket status
  • Open an assigned ticket where you are Request Management;
  • Change the status to in progress or pending where allowed;
  • Confirm the change.
 The message Status updated is displayed. The new status is shown in the ticket list. (The client marks the service complete, submits feedback, and closes the request.)
11.8.
Verify the empty list
  • Open Request Management when there are no managed requests.
 The page shows No requests yet. Approved client submissions will appear here for assignment and tracking.
Application 12: Assigned to me
12.1.
Open Assigned to me
  • Click Assigned to me in the left sidebar.
 The personal work table is displayed with the number of active assignments in the header and the columns Ticket, Client, Client division, Status, and Action.
12.2.
Verify an assigned ticket
  • Have a ticket assigned to your account;
  • Open the Assigned to me page.
 The ticket appears in the table with the status In Progress.
12.3.
Work on an assigned ticket
  • Click Open → in the Action column;
  • Optionally click View file;
  • Click Request messages to coordinate with the client.
 The ticket detail page opens. Notes or coordination happen through Request messages. When work is finished, the client marks the service complete, submits feedback, and closes the request.
12.4.
Verify the empty list
  • Open the Assigned to me page when no ticket is assigned to you.
 The page shows No assigned requests. When an admin assigns you to a request, it will appear here as In Progress.
Application 13: Admin: My Requests and Submit Request
13.1.
Open My Requests
  • Click REQUESTS, then My Requests, in the left sidebar.
 The page lists your own support request submissions (separate from Request Management), with a way to open Submit Request.
13.2.
Open Submit Request
  • Click REQUESTS, then Submit Request, in the left sidebar.
 The Submit Request page is displayed so you can file a request as a requester using published forms.
13.3.
Submit a request as Admin
  • Select a published form;
  • Complete the required fields;
  • Click Submit request.
 The request is filed under your account and appears in My Requests with the first step of the configured workflow.
Application 14: Admin: Reports
14.1.
Open Reports
  • Click MAIN, then Reports, in the left sidebar.
 The Reports page is displayed for your published forms. When you have no published forms, it shows You have no published forms yet. Publish a form from the Form Builder to build its report.
14.2.
Select a form and period
  • Choose a Form from the dropdown;
  • Choose a Year and Month (or All months).
 The report scope updates to the selected form and period. The closed-ticket count for that range is shown when a report format exists.
14.3.
Configure Report settings
  • Click Report settings;
  • For each form field, choose a display type (Donut chart, Pie chart, Bar chart, Column chart, Number tiles, Table list, or Not shown);
  • Click Save on each row you want, then Apply changes.
 The report format is saved. The page shows the configured cards for closed tickets of that form.
14.4.
Verify a form with no report format
  • Select a published form that has no report settings yet.
 The page shows No available report with steps to click Report settings, pick a chart or table for each field, and Apply changes.
14.5.
Verify chart cards
  • Open a form that already has report settings and closed tickets.
 Each configured field is shown as its selected chart or table. Fields set to Not shown are counted as hidden.
